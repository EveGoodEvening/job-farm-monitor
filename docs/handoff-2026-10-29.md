# Handoff — 2026-10-29

I've implemented the whole plan. Nothing is installed into the real `~/.claude`, `~/.codex` or `~/.omp` configs. Every automated check passes, but these still need you:
- the three platform deploys;
- installing the hooks on this machine and trusting them in Codex;
- running the interactive end-to-end matrix.

## Test results

- Build, typecheck and lint pass across all four packages.
- Tests: core 233, server 107, web 51 and local 74 pass. The Cloudflare Durable Object tests (23) pass in the local Cloudflare runtime.
- The Railway Docker image builds, serves the dashboard, and keeps its data across a container restart.
- `vercel build` succeeds offline, in a copy of the repo.
- End to end: `local/install.sh` installed the hooks into a temporary home directory, and a real `claude -p` run reported to the local Node server. The card had the right title, progress line and last reply.
- Screenshots at 375px and 1280px, light and dark, show the sections in the right order, at most 4 progress lines per card, and no horizontal scrolling.
- Wrong tokens get 401 on `/api/state`, `/api/sessions/:key` and `/api/ingest`. The login cookie is HttpOnly and SameSite=Lax, and gets Secure over https.
- A review found 18 bugs that held up under a second independent check, and all 18 are fixed with tests. The most serious:
  - One oversized event could block the whole outbox.
  - A permission prompt inside a subagent never cleared.
  - The emitter could exit with code 2 under dash, which blocks the agent's tool call.
  - oh-my-pi `/branch` and `/fork` were not tracked.
  - Ended sessions stayed on the dashboard past their 1-hour window.

## Changes from the plan

- `@cloudflare/vitest-pool-workers` 0.23.0 doesn't support vitest 5 and has been renamed, so I used `@cloudflare/vitest-plugin` 1.4.10.
- Vercel's Hono preset picked the wrong entry file and dropped the shared core package from the deployed function. The fix is a root `packages/server/index.js` that loads a bundled entry with core built in.
- Real captures from Claude and Codex turned up behaviour the plan didn't cover, now handled:
  - Codex asks questions through `request_user_input_async`, whose PostToolUse fires before the user has answered.
  - Codex doesn't send SessionEnd when you `/exit` an interactive session. A new session in the same pane now ends the old card.
  - Claude sends a permission request right after AskUserQuestion; it no longer replaces the question.
- If an oh-my-pi subagent can't find its parent session, it still gets its own card. Subagents run in the same process, so in practice this shouldn't happen.
